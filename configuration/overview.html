Skyhook

Configuration overview

Skyhook uses YAML configuration. The files are not rewritten when the terminal remembers a model.

File selection and layering

With --config path.yaml, Skyhook loads only that file. It does not search for or merge user or workspace configuration, even if the explicit file fails to load. The contents are always parsed as YAML, regardless of the filename suffix.

Without --config, Skyhook:

  1. Tries $XDG_CONFIG_HOME/skyhook/config.yaml, when that environment variable is set.
  2. On any read, YAML parse, or structural error, tries $HOME/.config/skyhook/config.yaml. At most one user file is selected; the two user files are never merged.
  3. Overlays <resolved workspace>/.skyhook/config.yaml if it exists. --workspace PATH selects the workspace; otherwise it is the invocation directory. No ancestor workspace configurations are loaded. An unreadable or invalid workspace file is an error.

Automatic discovery uses only config.yaml, not config.yml or config.toml; there is no TOML fallback.

Missing optional user files are fine: a complete workspace-only configuration can be used. A broken user file is not silently treated as missing if no fallback succeeds. The effective configuration must be valid; defaults are applied after merging.

Mappings merge recursively; sequences and scalar values replace the earlier value. The exception is named entries under targets and modes: a workspace entry replaces the whole user entry of the same name, without inheriting omitted fields. For example, targets.build replaces that target’s SSH, authentication, workspace, and routing settings; modes.general replaces that mode’s capabilities, instructions, and hint. Other named entries remain available. An explicit null replaces the earlier value: it clears an optional field, but is not a deletion operator for map entries. Required fields and named entries must still have valid values.

Example: user models, workspace targets

Keep provider/model definitions in the selected user config.yaml:

providers:
  openai:
    kind: "openai"
    base_url: "https://api.openai.com/v1"
    api: "responses"
    api_key_env: "OPENAI_API_KEY"

models:
  default:
    provider: "openai"
    model: "gpt-5.6"
    max_context: 1050000
    max_output: 128000

targets:
  bastion:
    type: "ssh"
    host: "bastion.example.com"

  build:
    type: "ssh"
    host: "old-build.internal"
    via: "bastion"
    ssh:
      auth:
        kind: "key"
        path: "~/.ssh/old-build"

Then use this <workspace>/.skyhook/config.yaml:

modes:
  general:
    capabilities: ["read", "write", "exec", "targets"]

targets:
  build:
    type: "ssh"
    host: "new-build.example.com"
    workspace: "/srv/project"

The effective configuration retains providers.openai, models.default, and targets.bastion. A named mode or target is replaced whole, not merged: modes.general grants exactly the listed capabilities, and targets.build uses the new host and workspace, with default authentication/routing behavior: neither the old key nor via: "bastion" survives. If a route or key is needed, repeat it explicitly in the workspace entry.

Trust boundary: workspace configuration is full configuration, not a restricted project hint. It can change approvals, modes, provider credential commands, and MCP server startup. Review it before starting Skyhook in an untrusted checkout.

YAML syntax and strings

Each file must contain a single YAML document with a mapping (object) at its root. Empty or comment-only documents, null roots, and sequence or scalar roots are rejected. An empty mapping ({}) is a valid no-op workspace overlay, but an empty effective configuration is invalid.

Values must be JSON-compatible: mappings with string keys, sequences, strings, booleans, finite numbers, and null. Duplicate keys, non-string keys, custom tags, non-finite numbers, multiple documents, and YAML << merge keys are rejected. Anchors and aliases are supported with bounded expansion. YAML merge keys are unrelated to Skyhook’s file layering.

Use indentation for nested settings, not dotted table headers. Quote values that must stay strings, especially numeric-looking SSH options and environment values: ServerAliveInterval: "15" and WORKERS: "4", not unquoted numbers. Actual numeric settings such as max_context remain numbers.

For multiline instructions or shell-command strings, a literal block scalar preserves line breaks:

modes:
  readonly:
    capabilities: ["read", "network"]
    instructions: |-
      Investigate and report.
      Do not change anything.

|- omits the final newline; use | if the string should end with a newline. Folded blocks (> or >-) turn ordinary line breaks into spaces, so use them only when that is intended. MCP start_command remains a sequence of argument strings, not a shell-command block.

Migrating from TOML

Manually convert the contents of each old config.toml to YAML, then rename it to config.yaml. Replace table headers with nested mappings and key = value assignments with key: value; keep the same configuration keys, values, and model declaration order. Check quoting and multiline string whitespace rather than only changing punctuation. Update explicit --config paths too. Renaming alone does not convert TOML, and Skyhook does not convert files automatically or fall back to the old format. Use skyhook dump config to validate and inspect the effective YAML.

Paths and environment

Relative MCP cwd values resolve against the directory of the source file defining that value. A user-defined cwd keeps its user-file base when other MCP fields are overlaid; a workspace-defined cwd uses the workspace config’s directory (<workspace>/.skyhook), not the workspace root.

The CLI always stores and discovers sessions in <workspace>/.skyhook/sessions, including headless execution and resume. It does not search other workspaces or honor session_root overrides. Remote paths resolve on the selected execution target. The workspace is a base directory, not filesystem isolation.

The CLI loads .env from the invocation directory, with existing process environment variables taking precedence. Neither --workspace nor --config changes that location. See authentication.

Inspect without starting a session

skyhook dump --workspace /path/to/project         # Same as dump config
skyhook dump config --workspace /path/to/project --approve-all
skyhook dump config --config ./standalone.yaml    # Explicit file only

These commands write resolved effective YAML to stdout and source paths/diagnostics to stderr. They apply defaults and applicable CLI policy overrides without requiring API credentials, starting MCP servers, or making network requests. Exit status is zero for a valid dump and nonzero if valid configuration cannot be produced. See dump for selectors and incompatible options.

Configuration areas

  • Providers and models: named API connections, full model IDs, context/output limits, reasoning replay, and connection recovery.
  • Authentication: environment variables, secret-manager commands, .env, and Skyhook-owned Codex login.
  • Permissions and capabilities: approve_all, modes, and their exact capability allowlists.
  • Execution targets: SSH destinations, origins, routing, and authentication.
  • MCP servers: trusted local server startup and imported tools.

Complete example

This is included from the repository’s single maintained config.example.yaml. It demonstrates multiple providers; remove unused profiles or supply their credentials before running a session. For a minimal configuration, follow your first session.

# The interface remembers the most recently selected model.
# With no saved selection, the first declared model below is used.
# Set to true to skip interactive approval for every tool call.
approve_all: false
# The mode a new session starts in: the built-in general, or one declared below.
# default_mode: "general"

# Modes are named permission presets. A mode's capabilities are an exact allowlist ([] grants
# none); add "targets" for remote-target tools, arguments, JavaScript APIs, and guidance.
# Interaction is supplied by the terminal and absent from batch jobs, never listed here.
# Optional instructions are added to the system prompt of an agent running in the mode.
# A hint, on a mode or a model, offers it to agents starting a child; others cannot be chosen.
# The terminal switches modes with Tab/Shift+Tab in the composer; --mode picks the starting one.
# This built-in mode always exists; declare it to change what it grants:
# modes:
#   general:
#     capabilities: ["read", "write", "exec", "network", "agents", "mcp"]
#
#   readonly:
#     capabilities: ["read", "network"]
#     instructions: "Investigate and report. Do not change anything."
#     hint: "Look things up without changing anything"

# The CLI loads .env from its invocation directory (not --workspace or the config directory).
# Existing process environment variables take precedence; no parent-directory search.
# Host environment and .env values are not forwarded to remote targets.
providers:
  openai:
    kind: "openai"
    base_url: "https://api.openai.com/v1"
    api: "responses"
    api_key_env: "OPENAI_API_KEY"

  anthropic:
    kind: "anthropic"
    base_url: "https://api.anthropic.com/v1"
    api_key_env: "ANTHROPIC_API_KEY"
    # Alternatively, remove api_key_env and retrieve a key lazily on the first request:
    # api_key_command: "op read 'op://Private/Anthropic/api-key'"
    # Runs via /bin/sh -c on the host; trimmed stdout is cached for this provider.
    # Also supported by OpenAI-compatible providers; cannot be combined with api_key_env.

  # Run `skyhook auth login` (or `skyhook auth login --headless`) first.
  # Credentials belong to Skyhook; official Codex client credentials are never accessed.
  codex:
    kind: "codex"

  # Keyless local llama.cpp endpoint; the model alias matches --alias below.
  # Example text-only server (requires enough memory for the configured context):
  # llama-server --model /path/to/Qwen3.8-27B.gguf --alias qwen3.8-27b \
  #   --host 127.0.0.1 --port 8080 --ctx-size 262144 --parallel 1 --n-predict 131072
  local:
    kind: "openai"
    base_url: "http://127.0.0.1:8080/v1"
    api: "chat_completions"
    # Chat-only, per-provider. Default "reasoning_content" replays returned reasoning.
    # Use "reasoning" for that wire convention, or "unsupported" to keep it local only.
    # Other protocols replay native reasoning automatically and do not accept this option.
    # chat_reasoning_replay: "reasoning_content"
    # Defaults allow long local-model prefills. Startup applies to EACH HTTP attempt.
    # startup_timeout_secs: 600
    # read_idle_timeout_secs: 600

# Published model limits; smaller budgets can be chosen for cost/latency.
models:
  # https://developers.openai.com/api/docs/models/gpt-5.6-sol
  openai:
    provider: "openai"
    model: "gpt-5.6"
    reasoning: "high"
    max_context: 1050000
    max_output: 128000
    supports_images: true

  # https://platform.claude.com/docs/en/models/sonnet-4-6/overview
  sonnet:
    provider: "anthropic"
    model: "claude-sonnet-4-6"
    reasoning: "high"
    max_context: 1000000
    max_output: 128000
    supports_images: true

  # Codex's catalog advertises a maximum context of 872000 (default: 272000).
  # https://github.com/openai/codex/blob/main/codex-rs/models-manager/models.json
  # max_output is required profile metadata, but is not sent to the Codex endpoint.
  # It does not control the 80%-of-context compaction threshold.
  codex:
    provider: "codex"
    model: "gpt-5.6-sol"
    reasoning: "high"
    max_context: 872000
    max_output: 128000
    supports_images: true

  # https://huggingface.co/Qwen/Qwen3.8-27B
  local:
    provider: "local"
    model: "qwen3.8-27b"
    # Native context; match the llama-server per-slot context, not extended-context claims.
    max_context: 262144
    # Chosen total-generation cap matching --n-predict, NOT a published hard model limit.
    # Reasoning and final text share this allowance and the overall context window.
    max_output: 131072
    # The text-only server above has no multimodal projector configured.
    supports_images: false
    # Adding a hint makes the model available to be used for delegation by other agents
    hint: "Local model, good at exploration and logic but not writing"

# MCP servers are optional; an absent/empty mcp mapping adds no tools or prompt guidance.
# Commands in this user config are trusted: startup runs without model approval,
# only on the local root/session host, never on a selected SSH target.
# Global "mcp" capability is required before any server is launched or contacted.
# A server's tools additionally require ALL listed capabilities; otherwise hidden.
# Per-server capabilities defaults to [] (global mcp only, no approval prompt).
# Valid names: read, write, exec, network, targets, ssh_agent, agents, interactive, mcp.
# Skyhook imports tools only; discovery is frozen at startup. Failed servers warn
# and are skipped. Tools are available both directly and inside script. Native
# input schemas are kept unless open/conflicting, when input uses `arguments`.
#
# mcp:
#   files:
#     transport: "stdio"
#     start_command: ["my-mcp-server", "--root", "/srv/project"] # argv, not shell text
#     capabilities: ["read"]
#     startup_timeout_secs: 30  # Positive integer seconds; default 30.
#     call_timeout_secs: 120    # Positive integer seconds; default 120.
#     cwd: "mcp-work"           # Relative to this config file's directory.
#     env: { LOG_LEVEL: "warn" } # Startup process environment overrides, not secrets.
#
#   service:
#     transport: "streamable_http"
#     url: "http://127.0.0.1:8080/mcp" # Full MCP endpoint; legacy HTTP+SSE unsupported.
#     capabilities: ["read", "write"]
#     headers_env: { Authorization: "MY_MCP_AUTHORIZATION" } # Env var, not secret.
#     # The variable must be set to a valid HTTP header value, e.g. Bearer ...
#     # Missing/non-Unicode variables fail startup; empty values are passed through.
#     # Connect first. Start this optional local command ONLY if the endpoint is unreachable,
#     # never for authentication or protocol errors. cwd/env require start_command.
#     start_command: ["my-http-mcp-server", "--port", "8080"]
# Stdio requires start_command and rejects url/headers_env; HTTP requires url.
# Unknown fields/capabilities, invalid combinations, and invalid timeouts are errors.
